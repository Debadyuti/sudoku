# Phase 7: Distribution & Auto-Update System Design

**Status**: Design Phase (pre-implementation)  
**Approach**: Tauri + GitHub Releases for auto-update capability  
**Target**: Windows .exe with automatic update checking  

---

## Executive Summary

Phase 7 transforms the Sudoku game into a distributable Windows application with automatic updates. Users will receive a `.exe` installer, and the app will automatically notify them of new versions with one-click installation.

**Key Flow**:
```
Developer commits code → Tags release → GitHub Actions builds .exe 
→ Publishes to GitHub Releases → Users' apps auto-detect update 
→ One-click install → App restarts with new version
```

**Timeline**: ~4-6 hours implementation  
**Cost**: Free (GitHub Actions + Releases)

---

## Complete End-to-End Flow

### Phase A: Version Management (Local Development)

#### Step 1: Update Version in Code
**File**: `pyproject.toml`

```toml
[project]
name = "sudoku-game"
version = "1.0.0"  # ← Update this with each release
description = "Educational Sudoku solver with Material Design UI"
```

**Pattern**:
- Use semantic versioning: `MAJOR.MINOR.PATCH`
- `1.0.0` → Initial release (stable)
- `1.1.0` → New feature (hint system was added in Phase 6)
- `1.0.1` → Bug fix only
- Examples:
  - v1.0.0: Initial Phase 1-4 release
  - v1.1.0: After Phase 6 (add hint/stats/undo)
  - v1.2.0: After new feature later
  - v1.0.1: Critical bug fix

#### Step 2: Update Tauri Manifest
**File**: `src-tauri/tauri.conf.json` (created in Phase 7)

```json
{
  "package": {
    "productName": "Sudoku Game",
    "version": "1.0.0"  // Must match pyproject.toml
  },
  "build": {
    "beforeDevCommand": "npm run dev",
    "devUrl": "http://localhost:3000",
    "frontendDist": "../dist"
  },
  "app": {
    "windows": [
      {
        "title": "Sudoku Game",
        "width": 950,
        "height": 850,
        "resizable": false
      }
    ]
  },
  "updater": {
    "active": true,
    "endpoints": [
      "https://github.com/YOUR_USERNAME/sudoku/releases/latest/download/latest.json"
    ],
    "dialog": true,
    "pubkey": "YOUR_SIGNING_KEY"  // Generated by Tauri
  }
}
```

#### Step 3: Commit Changes
```bash
git add pyproject.toml src-tauri/tauri.conf.json
git commit -m "Bump version to 1.1.0 - Add hint system, statistics, undo/redo"
```

**Result**: Changes on `master` branch, ready for release

### Phase C: Automated Build (GitHub Actions)

#### Step 5: GitHub Actions Builds .exe
**File**: `.github/workflows/release.yml` (created in Phase 7)

```yaml
name: Build and Release

on:
  push:
    tags:
      - 'v*'  # Trigger only on version tags (v1.0.0, v1.1.0, etc.)

jobs:
  release:
    runs-on: windows-latest
    
    steps:
      - uses: actions/checkout@v3
      
      - name: Setup Python
        uses: actions/setup-python@v4
        with:
          python-version: '3.11'
      
      - name: Setup Node
        uses: actions/setup-node@v3
        with:
          node-version: '18'
      
      - name: Install Rust
        uses: actions-rs/toolchain@v1
        with:
          toolchain: stable
          target: x86_64-pc-windows-msvc
      
      - name: Build frontend
        run: |
          npm install
          npm run build
      
      - name: Build Tauri app
        run: |
          npm run tauri build
      
      - name: Create latest.json (for auto-update)
        run: |
          $version = "${{ github.ref }}" -replace "refs/tags/v", ""
          @{
            version = $version
            notes = "See https://github.com/YOUR_USERNAME/sudoku/releases/tag/v$version"
            pub_date = (Get-Date -Format "yyyy-MM-ddTHH:mm:ssZ")
            platforms = @{
              "windows-x86_64" = @{
                signature = (Get-Content "src-tauri/target/release/bundle/msi/*.exe.sig")
                url = "https://github.com/YOUR_USERNAME/sudoku/releases/download/v$version/sudoku-game_${version}_x64-setup.exe"
              }
            }
          } | ConvertTo-Json | Out-File -FilePath "latest.json"
      
      - name: Upload to GitHub Release
        uses: softprops/action-gh-release@v1
        with:
          files: |
            src-tauri/target/release/bundle/msi/*.exe
            latest.json
        env:
          GITHUB_TOKEN: ${{ secrets.GITHUB_TOKEN }}
```

**What This Does**:
1. ✅ Watches for git tags (v1.1.0, etc.)
2. ✅ Clones code on GitHub's Windows machine
3. ✅ Installs dependencies (Python, Node, Rust)
4. ✅ Builds Tauri .exe (typically ~50-80MB)
5. ✅ Generates `latest.json` (update manifest for Tauri)
6. ✅ Uploads both to GitHub Releases
7. ✅ Takes ~15-20 minutes

**Output**:
```
GitHub Releases for v1.1.0/
├── sudoku-game_1.1.0_x64-setup.exe  (installer)
└── latest.json  (update manifest - Tauri reads this)
```

### Phase D: User Download (First Time)

#### Step 6: User Gets Initial Release
**Process**:
1. User visits: `https://github.com/YOUR_USERNAME/sudoku/releases`
2. Clicks "Latest Release" (v1.1.0)
3. Downloads `sudoku-game_1.1.0_x64-setup.exe`
4. Runs installer → Installs to `C:\Program Files\Sudoku Game\`
5. Launches app

**First Launch**:
- App reads version from `tauri.conf.json` (v1.1.0)
- Tauri checks GitHub Releases API
- No update available (already on latest)
- App runs normally

### Phase E: User Receives Update (Ongoing)

#### Scenario: You Release v1.2.0

**Developer Side** (you):
```bash
# Update code with new features
git add src/
git commit -m "Add puzzle difficulty analyzer"

# Update version
sed -i 's/version = "1.1.0"/version = "1.2.0"/' pyproject.toml
sed -i 's/"version": "1.1.0"/"version": "1.2.0"/' src-tauri/tauri.conf.json

git add pyproject.toml src-tauri/tauri.conf.json
git commit -m "Bump version to 1.2.0"

# Tag and push
git tag v1.2.0
git push origin master v1.2.0
```

**Result**: GitHub Actions starts building

**User Side** (next time they launch app):
```
User launches Sudoku Game (running v1.1.0)
    ↓
Tauri startup check:
  - Reads tauri.conf.json (current: v1.1.0)
  - Fetches https://github.com/YOUR_USERNAME/sudoku/releases/latest/download/latest.json
  - Sees latest.json has version: 1.2.0
    ↓
Tauri compares: 1.2.0 > 1.1.0 → Update available!
    ↓
User sees dialog:
  ┌─────────────────────────────────┐
  │ Update Available                │
  │ New version 1.2.0 available     │
  │ Current: 1.1.0                  │
  │                                 │
  │ [Install]  [Skip]               │
  └─────────────────────────────────┘
    ↓
User clicks [Install]
    ↓
Tauri downloads sudoku-game_1.2.0_x64-setup.exe (~60MB)
    ↓
Installation complete:
  ┌─────────────────────────────────┐
  │ Update installed successfully   │
  │ Restart app to apply changes    │
  │                                 │
  │ [Restart Now]  [Restart Later]  │
  └─────────────────────────────────┘
    ↓
User clicks [Restart Now]
    ↓
App restarts → runs v1.2.0
```

## Technical Architecture

### Directory Structure (Phase 7 adds)
```
sudoku/
├── .github/
│   └── workflows/
│       └── release.yml  ← GitHub Actions workflow
├── src-tauri/
│   ├── tauri.conf.json  ← Tauri config with updater settings
│   └── Cargo.toml       ← Rust dependencies
├── pyproject.toml       ← Version management
├── src/
│   ├── sudoku_game.py
│   ├── ui.py
│   └── ...
└── README.md
```

### Version Flow

```
pyproject.toml (source of truth)
    ↓
git tag v1.1.0
    ↓
GitHub Actions reads tag
    ↓
Builds src-tauri/ with version 1.1.0
    ↓
Publishes sudoku-game_1.1.0_x64-setup.exe
    ↓
Creates latest.json with version: 1.1.0
    ↓
User's app checks latest.json
    ↓
If latest > current → offer update
```

### File: latest.json (Update Manifest)

**Example**:
```json
{
  "version": "1.2.0",
  "notes": "See https://github.com/debadyuti/sudoku/releases/tag/v1.2.0",
  "pub_date": "2026-08-25T14:30:00Z",
  "platforms": {
    "windows-x86_64": {
      "signature": "SIGNATURE_HASH_HERE",
      "url": "https://github.com/debadyuti/sudoku/releases/download/v1.2.0/sudoku-game_1.2.0_x64-setup.exe"
    }
  }
}
```

**Tauri uses this to**:
1. ✅ Check if update available (compare versions)
2. ✅ Get download URL
3. ✅ Verify integrity (signature check)
4. ✅ Show update notification

## Version Numbering Strategy

### Semantic Versioning: MAJOR.MINOR.PATCH

| Version | When | Example |
|---------|------|---------|
| **1.0.0** | Initial release | Phases 1-5 complete (core features) |
| **1.1.0** | New feature(s) | Phase 6 complete (hint + stats + undo) |
| **1.1.1** | Bug fix only | Fix menu rendering bug |
| **1.2.0** | New feature | Phase 7.5 (puzzle difficulty analyzer) |
| **2.0.0** | Major redesign | Complete UI rewrite or major breaking change |

**Rule**: Only increment one number per release

## Risk Mitigation

### Potential Issues

| Risk | Mitigation |
|------|-----------|
| **Workflow fails** | Test with v0.9.0 tag first (non-release) |
| **Signature mismatch** | Tauri generates keys automatically; use them |
| **Large exe size** | Normal for Tauri (~60-80MB); document this |
| **Update doesn't trigger** | Users must restart app; dialog explains this |
| **GitHub token missing** | GitHub Actions provides default token automatically |
| **User skips updates** | They can manually download from Releases page |
